# Two-minute portable handoff demo

[//]: # (ob:894f03f7)
This example contains two kinds of portable provenance:

[//]: # (ob:597a7aa9)
- `strategy.md` and `strategy.html` carry the same two-version native ledger.
- `proposal.docx` travels with `proposal.provenance.json`, a semantic evidence
  sidecar that verifies the Word document but does not claim revision history.

[//]: # (ob:fb418795)
## Inspect native history

[//]: # (ob:9d8064bc)
Copy the Markdown artifact into a clean repository and inspect its history:

[//]: # (ob:6f729c3c)
```sh
mkdir proofpress-handoff && cd proofpress-handoff
git init
npm install --save-dev proofpress
curl -LO https://raw.githubusercontent.com/chenmingtang830/proofpress/main/examples/portable-handoff/strategy.md
npx --no-install proofpress inspect strategy.md
npx --no-install proofpress import strategy.md
npx --no-install proofpress log strategy.md
npx --no-install proofpress diff strategy.md
npx --no-install proofpress verify strategy.md
```

[//]: # (ob:80c71b17)
1. `inspect` checks the embedded capsule without requiring a local ledger.
2. `import` reconstructs the local ledger from the file alone.
3. `log` and `diff` expose the two admitted versions and their actual changes.
4. `verify` checks the recorded claims against the computed change.

[//]: # (ob:20be43e3)
`strategy.md` contains a real v1 → v2 record using fictional, non-sensitive
content. Stated reasons and actor identities are recorded claims, not
independently proven facts.

[//]: # (ob:af4a73c6)
To run the same flow with static HTML, download `strategy.html` instead and
substitute that filename in the commands. Its Proofpress metadata uses hidden
HTML elements and `data-proofpress-id` anchors rather than Markdown comments.

[//]: # (ob:9704e00d)
## Verify a DOCX handoff

[//]: # (ob:7d6ecea3)
Download the Word artifact and its evidence record together:

[//]: # (ob:486c83a1)
```sh
curl -LO https://raw.githubusercontent.com/chenmingtang830/proofpress/main/examples/portable-handoff/proposal.docx
curl -LO https://raw.githubusercontent.com/chenmingtang830/proofpress/main/examples/portable-handoff/proposal.provenance.json
npx --no-install proofpress provenance verify proposal.docx \
  --evidence proposal.provenance.json
```

[//]: # (ob:e317012a)
The sidecar records canonical OOXML semantic evidence. Repacking the DOCX ZIP
can still verify, while changing its document content fails verification. The
sidecar is integrity evidence—not a native revision ledger, digital signature,
or proof of the creator's identity—and should travel with the artifact.
